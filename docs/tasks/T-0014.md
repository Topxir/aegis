# T-0014 — Реальная международная (Cross-Border / Cross-Country) сетевая доставка зашифрованных капсул по TCP/HTTP и SOCKS5/Tor между ПК и Android
Модуль(и): `aegis-server`, `aegis-transport`, `aegis-protocol`, `aegis-ffi`, `aegis-ui-desktop`, `aegis-ui-android`, `builds/` · Фаза: 10 (Global Cross-Border Live Networking) · Приоритет: критический · Тип: feature | security

## Цель
Обеспечить полноценную живую переписку через Интернет между людьми из разных стран и сетей (ПК ↔ ПК, Android ↔ Android, Android ↔ ПК) через любой сервер `aegis-serverd` (на VPS со статическим IP, проброшенном порту или через Tor/SOCKS5):
1. **В `aegis-server` (`handle_http_request` и `aegis-serverd`):**
   - Поддержка реальной маршрутизации по идентификатору очереди в `POST /api/v1/queue/send?queue=<64_hex>` и `POST /api/v1/queue/poll?queue=<64_hex>` с возвратом шестнадцатеричных зашифрованных капсул `frames_hex` получателю при сохранении обратной совместимости с тестами.
   - Поддержка приёма шестнадцатеричных уже выровненных (`256..16384 B`) крипто-капсул без двойного паддинга.
2. **В `aegis-protocol` и `aegis-transport`:**
   - Единый кроссплатформенный формат международной E2EE-капсулы (`seal_cross_border_capsule` / `open_cross_border_capsule` на базе RFC 8439 ChaCha20-Poly1305 + SHA-256 + `pad_frame` 256..16384 B), побитово совместимый между Rust (Desktop) и Kotlin/JCE (Android API 28+).
   - Реальный сетевой клиент в `aegis-transport`:
     - Прямая отправка и опрос очередей по TCP/HTTP (`send_capsule_over_tcp`, `poll_capsules_over_tcp`);
     - Полноценный клиент **RFC 1928 SOCKS5h (`send_capsule_via_socks5`, `poll_capsules_via_socks5`)** с удалённым разрешением доменных имён и `.onion`-адресов через прокси/Tor без утечки DNS в локальной стране!
3. **В `aegis-ui-desktop` и `apps/aegis-android`:**
   - Живая синхронизация с сервером (`Синхронизировать с узлом / Принять капсулы из сети`), настройка общего кода канала (`Queue ID` / `Shared Channel Key`) для связи с собеседником из любой страны, автоматическая отправка зашифрованных капсул в сеть при отправке сообщения и приём входящих капсул с расшифровкой ChaCha20-Poly1305.
4. Написать живой интеграционный тест с поднятием реального TCP-сервера и обменом зашифрованными капсулами между двумя клиентами по сети, пересобрать глобальные билды в `builds/` и запушить в GitHub.

## Критерии приёмки
- [x] `aegis-server` маршрутизирует реальные очереди по `?queue=<64_hex>` и отдаёт `frames_hex` при опросе.
- [x] `aegis-transport` реализует живой TCP и SOCKS5h сетевой транспорт для отправки и получения 256..16384 B капсул через границу/интернет.
- [x] Desktop (`aegis-ui-desktop`) и Android (`AegisRustBridge.kt` + `AegisComposeApp.kt`) используют побитово совместимый формат капсул RFC 8439 ChaCha20-Poly1305 и умеют отправлять/принимать сообщения через реальный сервер по IP/домену.
- [x] Живой TCP тест обмена сообщениями между клиентами через сервер проходит на 100%, глобальные билды в `builds/` обновлены и отправлены в GitHub.
