# T-0011 — Фаза 8: Стартовые анонимные серверы со статическим IP (без обязательного Tor), сборка APK/Desktop/Server в папку `builds/` и релиз на GitHub
Модуль(и): `aegis-directory`, `aegis-transport`, `aegis-launcher`, `aegis-server`, `aegis-ffi`, `aegis-ui-desktop`, `aegis-ui-android`, CI · Фаза: 8 · Приоритет: критический · Тип: feature | contract-change | security

## Цель
1. Настроить встроенные стартовые анонимные серверы со **статическими IP-адресами и хостами** (`Official ✓✓` и `Verified ✓`) с поддержкой **прямого подключения без обязательного Tor/VPN** (чтобы любой пользователь мог подключиться сразу «из коробки» в 1 клик, а Tor/SOCKS5 оставались опциональными), плюс переключение/добавление своего статического IP в клиенте и готовый 1-клик скрипт развёртывания на любом VPS со статическим IP (`--bind=0.0.0.0:8443`).
2. Собрать готовые релизные артефакты в отдельную структурированную папку `builds/`:
   - `builds/android-apk/` — реальный подписанный Android APK (`aegis-messenger-release.apk` и `aegis-messenger-debug.apk`), SHA-256 чексуммы, скрипт пересборки и автономная копия Android-проекта;
   - `builds/desktop/` — скомпилированный бинарник `aegis-desktop.exe` + батники быстрого запуска GUI и автотеста;
   - `builds/server/` — скомпилированный бинарник `aegis-serverd.exe` + готовые конфиги (`docker-compose.yml`, `cloud-init.yaml`, `deploy-static-ip-vps.sh`, `run-local-server.bat`) для мгновенного запуска стартового сервера на статическом IP.
3. Настроить GitHub Actions workflow (`.github/workflows/ci.yml` и `.github/workflows/release-apk.yml`) для автоматической сборки APK и бинарников на GitHub и запушить всё в репозиторий `https://github.com/Topxir/aegis.git`.

## Критерии приёмки
- [x] В `aegis-directory` (`BuiltInDirectory`) встроены стартовые серверы со статическими IPv4 адресами (`static_ipv4: Option<[u8; 4]>`, прямые `aegis://<STATIC_IP>:8443` ноды `Official ✓✓` и `Verified ✓`), не требующие обязательного Tor, а также резервный `.onion` узел.
- [x] В `aegis-transport`, `aegis-launcher`, `aegis-server` (`aegis-serverd --bind=0.0.0.0 --port=8443`), `aegis-ui-desktop` и `aegis-ui-android` подключение к стартовым статическим IP работает напрямую по умолчанию (`kill_switch_enabled: false` для прямого стартового профиля, без блокировки обычных пользователей без Tor), с возможностью переключения стартового сервера и ввода своего статического IP в 1 клик.
- [x] Проведён параллельный аудит всех модулей и исправлены все найденные баги (включая ресурсы Android APK `res/xml/no_backup_rules.xml`, биндинг `aegis-serverd` на внешний интерфейс `0.0.0.0` для VPS со статическим IP и др.).
- [x] Собраны и проверены готовые релизные билды в папке `builds/` (`builds/android-apk/`, `builds/desktop/`, `builds/server/`).
- [x] Все тесты (`cargo test --workspace --all-targets`), `clippy`, `rustfmt`, проверка секретов и сборка APK проходят без ошибок; изменения отправлены (`git push`) в GitHub.

## Вне рамок (чего НЕ делать)
- Не делать Tor обязательным для входа и переписки.
- Не ослаблять E2EE, пиннинг ключей серверов (`ServerKeyPin`) и политику `No-IP-Logs` на сервере.

## Риски / модель угроз (кратко)
- При прямом подключении к стартовому серверу по статическому IP (без Tor/VPN) провайдер видит факт соединения со статическим IP сервера, но не видит содержимое (E2EE PQXDH + Double Ratchet + паддинг `256..16384 B`), а сам сервер работает в режиме `Zero-IP-Logs` (только в ОЗУ) и не знает ников (`OPAQUE`) и графа контактов (`Sealed Sender`).
