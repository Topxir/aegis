# T-0017 — Security Reset: аудированное ядро, invite-only идентичность, встроенный Tor/OHTTP

Модуль(и): `aegis-crypto`, `aegis-identity`, `aegis-storage`, `aegis-protocol`,
`aegis-transport`, `aegis-server`, `aegis-ffi`, `aegis-ui-desktop`,
`apps/aegis-android`, документация.
Фаза: 13 (Security Reset). Приоритет: критический.
Тип: security | architecture | planning.

**Статус: rev.2 УТВЕРЖДЕНА владельцем 2026-10-30. Phase 0 — документы/ADR; код не меняется.**

## Цель

1. Зафиксировать честную модель угроз v2 и протокол v2.
2. Прекратить разработку функций поверх самописной криптографии.
3. Заменить криптографический, идентификационный, сетевой и storage-фундамент
   на проверенные библиотеки и публичные спецификации.
4. Перейти на invite-only идентичность без глобального ника; seed-only по
   умолчанию + opt-in OPAQUE-аккаунт для восстановления.
5. Сделать встроенный Tor + OHTTP режимом по умолчанию; прямой IP — только
   явный opt-in с предупреждением.
6. Довести до MVP: 1:1 текст + файлы на Android и Desktop.
7. Группы через MLS — в бете после стабилизации 1:1, максимум 20.
8. iOS — после стабилизации ядра.
9. Репозиторий приватный до внутреннего red team; затем public alpha с
   меткой «unaudited»; внешний аудит — до 1.0.
10. Бэкап — только явный зашифрованный экспорт; автоматического cloud
    backup нет.

### Phase 1 — аудированное ядро 1:1

- [ ] Нет самописных примитивов: SHA-256, HMAC, HKDF, ChaCha20, Poly1305,
      AEAD, X25519, ML-KEM, XEdDSA, ratchet — только audited crates.
- [ ] PQXDH + Double Ratchet через libsignal (pinned commit); никакого
      своего комбинатора.
- [ ] Identity: seed → `AIK`/`DIK` (Curve25519 XEdDSA) + ML-KEM; invite v2;
      safety number; key-change warning.
- [ ] Invite v2: `account_pub`, `device_pub`, `device_credential`, prekey
      bundle, `inbox_id`; без `max_uses`.
- [ ] Inbox: `inbox_id = H(read_token)`; no registration; read auth.
- [ ] Локальное хранилище: SQLCipher; ключ в Android Keystore/StrongBox или
      OS keyring; duress wipe; auto-lock.
- [ ] CLI-тест: два клиента обмениваются 1:1 сообщениями; сервер не видит
      открытый текст и идентичность отправителя.
- [ ] RFC/NIST test vectors; libsignal vectors; property tests; fuzzing
      парсеров.
- [ ] `cargo deny`, `cargo audit`, `cargo vet`; SBOM.

### Phase 2 — транспорт, доставка и opt-in OPAQUE

- [ ] TLS 1.3 через `rustls`; никакого plain HTTP; пиннинг ключа relay.
- [ ] Встроенный Tor через `arti-client`; пользователь ничего не
      устанавливает.
- [ ] OHTTP для API; gateway отделён от relay.
- [ ] Blind relay: inbox ID, one-time tokens, TTL, RAM-only, no logs.
- [ ] Blob store для файлов: шифрование, паддинг, TTL, 3 реплики.
- [ ] Account service: OPAQUE RFC 9807 + Argon2id; encrypted seed-backup;
      signed device list; отдельно от relay.
- [ ] Seed-only режим работает без account service.
- [ ] E2E: 1:1 текст + файл между двумя CLI-клиентами через Tor.

### Phase 3 — Android/Desktop MVP

- [ ] Android (Compose) и Desktop (native Rust GUI, без webview) используют
      только `aegis-ffi`.
- [ ] QR-инвайт, safety number, key-change warning.
- [ ] Уведомления без содержимого; Android — UnifiedPush/self-hosted, не FCM
      по умолчанию.
- [ ] Duress PIN, panic wipe, запрет скриншотов.
- [ ] **Только явный зашифрованный экспорт**; no cloud backup.
- [ ] 1:1 текст + файлы стабильны 7 дней на тестовых устройствах.

### Phase 4 — группы beta и multi-device

- [ ] MLS через `openmls`; add/remove/epoch; forward secrecy.
- [ ] Группы ≤ 20 участников; pairwise-обёртка для сокрытия группы от relay.
- [ ] Multi-device: device list, подписанный `AIK`; шифрование на каждое

- [ ] OPAQUE device list sync (opt-in).
- [ ] Фаззинг, формальный анализ протокола, внутренний red team.

## Риски / модель угроз (кратко)

- **Критический:** текущее ядро самописное; любые новые функции поверх него
  увеличивают риск. Поэтому сначала reset, потом функции.
- **Интеграция libsignal/OpenMLS:** лицензии, размер, мобильная сборка,
  совместимость. Смягчение: ADR, spike, pinned commit, тесты.
- **Arti на Android:** батарея, фон, размер APK. Смягчение: relay fallback,
  профилирование, P2P только foreground.
- **OPAQUE account service:** дополнительный серверный сервис, login
  timing, offline guessing слабого пароля. Смягчение: отдельный оператор,
  OHTTP/Tor, Argon2id, сильный пароль, минимум данных.
- **App Store:** анонимный E2EE-мессенджер могут не пустить. Смягчение:
  прямой APK/F-Droid, честная политика, iOS позже.
- **Соло без бюджета:** выгорание и расползание scope. Смягчение: жёсткие
  phase gates, MVP 1:1 + файлы, группы в бете.
- **Аудит:** без денег его не будет. Смягчение: гранты (NLnet/OTF/Prototype
  Fund), public alpha после внутреннего red team, внешний аудит до 1.0.
- **Правовые риски:** анонимность + E2EE + abuse. Смягчение: client-side
  block/report, rate limits, прозрачная политика, юрисдикция.
