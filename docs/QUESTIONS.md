# Вопросы владельцу

| # | Вопрос | Статус | Ответ |
|---|---|---|---|
| Q-1 | Платформы старта: Android + десктоп, затем iOS? | ✅ | Да: старт Android + Desktop, позже iOS (см. D-0005). |
| Q-2 | Recovery и стандарты пароля? | ✅ | Строгий стандарт пароля (мин. длина, >= 3 заглавных, строчные, цифры, спецсимволы, проверка энтропии и защита от брутфорса через Argon2id + PoW). 24 слова не обязательны (опционально). OPAQUE-аккаунт — только opt-in; по умолчанию seed-only. |
| Q-3 | Модель сети: аккаунты на сервере или односторонние очереди? | ✅ | Relay-first: слепые очереди по `inbox_id = H(read_token)`, без регистрации inbox и без глобального ника. Идентичность — invite-only ключи; OPAQUE-аккаунт — только opt-in для восстановления seed/device list. Tor + OHTTP по умолчанию (D-0024, D-0025). |
| Q-4 | Группы и файлы в MVP или позже? | ✅ | MVP: 1:1 текст + файлы. Группы через MLS — в бете (Phase 4, ≤ 20). Звонки не делаем. |
| Q-5 | Лицензия AGPL-3.0 подходит? | ✅ | Да, AGPL-3.0 принята (см. D-0003). |
| Q-6 | Кто подписывает каталог серверов и сертификаты поддержки (один ключ или порог 2-из-3)? | ✅ | На старте 1 ключ фонда, но формат каталога и код (`aegis-directory`) изначально поддерживают пороговую схему M-of-N (Ed25519). |
| Q-7 | Нужна история после переустановки (зашифрованный бэкап) или «чистый лист»? | ✅ | По умолчанию локальное хранение; история — только **явный** зашифрованный экспорт (ключ из пароля через Argon2id). Автоматического cloud backup нет. OPAQUE seed-backup — только seed, не история чата. Мультиаккаунт до 3 профилей на устройстве бесплатно, свыше 3 — разблокировка через анонимный донат-токен (Privacy Pass / blind signature). |
| Q-8 | Бюджет на внешний аудит в Фазе 8? | ✅ | Внутренний red team, фаззинг, открытая спецификация и воспроизводимые сборки — Phase 5 rev.2. Внешний аудит — после финансирования, до 1.0. |
| Q-9 | Языки интерфейса на старте: RU + EN? | ✅ | Да, RU + EN со старта (см. D-0012). |
| Q-10 | Как настраиваем стартовые серверы? | ✅ | Каталог подписанных relay/account descriptors; по умолчанию Tor + OHTTP. Прямой IP — только явный opt-in с предупреждением. Launcher поднимает свой relay/account на VPS/Docker/onion. D-0019 в части прямого IP по умолчанию устарел (D-0024, D-0025). |
| Q-11 | Как собираем готовый Android APK и билды в отдельную папку `builds/`? | ✅ | Локальная сборка подписанного `.apk` (через портативный JDK 17 + Android SDK) и бинарников `aegis-desktop` / `aegis-serverd` в папку `builds/` (`builds/android-apk/`, `builds/desktop/`, `builds/server/`) + автосборка в GitHub Actions и пуш в GitHub (см. D-0020). |
| Q-12 | Что делаем с существующим Aegis после аудита 2026-10-30? | ✅ | Пока только план и спецификация, без изменений кода. Принят security reset (D-0024): сохранить UI/доки, заменить самописное ядро на audited crates. Rev.2 утверждена 2026-10-30 (D-0025, D-0026, T-0017). |
| Q-13 | Какая модель идентичности? | ✅ | Инвайты + ключи, без глобального ника. Seed-only по умолчанию; опционально OPAQUE-аккаунт для восстановления seed и списка устройств, без глобального ника. |
| Q-14 | Какой сетевой режим по умолчанию? | ✅ | Встроенный Tor (Arti) по умолчанию + OHTTP для API. Пользователь ничего не устанавливает. Прямой IP — только явный opt-in с предупреждением. |
| Q-15 | Когда открываем репозиторий? | ✅ | Приватный до внутреннего red team; затем public alpha с меткой «unaudited»; внешний аудит — до 1.0. |
| Q-16 | Когда делаем iOS? | ✅ | Сначала Android + Desktop; iOS после стабилизации ядра. Внешний аудит — до 1.0, не блокирует начало iOS после стабилизации. |
| Q-17 | Что считаем MVP? | ✅ | 1:1 текст + файлы; группы через MLS — в бете. Звонки не делаем. |
| Q-18 | Какие ресурсы у проекта? | ✅ | Соло, без бюджета. Внешний аудит — позже, после гранта/финансирования. |
| Q-19 | Какая модель identity key для 1:1/PQXDH? | ✅ | libsignal XEd25519: один Curve25519 identity key для DH и подписей. Отдельные Ed25519 + X25519 для PQXDH не используем; Ed25519 — только инфраструктура. |
| Q-20 | P2P onion в MVP или после relay? | ✅ | После MVP. MVP — relay-first; P2P начинается после стабилизации relay. |
