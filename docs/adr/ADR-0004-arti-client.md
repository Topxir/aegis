# ADR-0004 — arti-client для встроенного Tor

- Статус: **ПРИНЯТО**
- Дата: 2026-10-30
- Компоненты: `aegis-core::transport`, `aegis-ui-android`, `aegis-ui-desktop`
- Связанные решения: `D-0024`, `D-0025`, `D-0026`

## Контекст

Пользователь не должен устанавливать Tor/Orbot. Tor — режим по умолчанию;
прямой IP — только явный opt-in с предупреждением. Прототип не имеет
встроенного Tor (`B-0098`), а `TorArtiEmbedded` — только вариант enum.

## Решение

Использовать `arti-client` (Arti, Tor Project):

- crate: `arti-client`;
- версия: `0.47.0`;
- лицензия: MIT OR Apache-2.0;
- MSRV: 1.92;
- репозиторий: `https://gitlab.torproject.org/tpo/core/arti`;
- Tor-клиент запускается внутри процесса, без внешнего `tor` binary;
- bootstrap при старте; прогресс показывается в UI без утечки адресов;
- все relay/account/blob/key server соединения по умолчанию идут через
  Tor; OHTTP добавляет разделение IP/содержимого;
- onion-сервисы для relay — через Arti/`tor-hsservice` в Phase 2;
- P2P onion — после MVP, не в этой задаче;
- при недоступности Tor — fail closed, а не тихий прямой IP. Прямой режим
  только после явного opt-in и предупреждения.

## Почему Arti

- Официальная Rust-реализация Tor от Tor Project.
- Встраивается в Android/Desktop без установки Orbot.
- MIT/Apache-2.0 совместимы с AGPL-3.0-or-later.
- Позволяет контролировать circuits, изоляцию и bootstrap из кода.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| C Tor (`tor` binary) | Внешний процесс, сложнее Android, нужен менеджмент бинарника |
| Orbot | Пользователь должен устанавливать отдельное приложение |
| Прямой SOCKS5 прокси | Не анонимизирует; зависит от пользователя |
| Свой Tor | Запрещено |
| Без Tor | Противоречит цели и `D-0024` |

## Лицензия и AGPL

MIT OR Apache-2.0. Совместимо с AGPL-3.0-or-later. Сохранить уведомления
Tor Project и лицензии зависимостей.

## Аудит и происхождение

- Arti — проект Tor Project; Tor protocol хорошо изучен, но Arti моложе
  C Tor.
- Публичный аудит конкретной версии `0.47.0` не подтверждён.
- Внешний аудит интеграции Arti (bootstrap, leak protection, Android
  background) — до 1.0.
- При пине проверить OSV/RustSec, advisory Tor Project и changelog Arti.

## Известные CVE

На 2026-10-30 OSV не возвращает известных уязвимостей для
`arti-client 0.47.0`. Проверять при каждом обновлении; Arti быстро
развивается, поэтому пин и обновление — обязательны.

## Риски и ограничения

| Риск | Смягчение |
|---|---|
| Battery/CPU на Android | Профилирование; lazy bootstrap; foreground/background политика |
| Долгий bootstrap | UI-статус; таймауты; fallback на другой relay, не на прямой IP |
| DNS/WebRTC leak | Все соединения через Tor; запрет системного DNS для `.onion`; тесты |
| Arti менее зрел, чем C Tor | Пин; тесты; внешний аудит; возможность fallback на C Tor через ADR |
| Onion service сложность | Phase 2; отдельный spike; не в MVP |
| Нет аудита версии | Внешний аудит до 1.0 |

## План проверки

1. Bootstrap в тестовой сети; проверка, что трафик идёт через Tor.
2. Тест утечки DNS: `.onion` не резолвится системным DNS.
3. Тест kill switch: при падении Tor нет прямого соединения.
4. Тест Android background/doze: соединение восстанавливается.
5. Замер батареи и размера APK.
6. Тест onion service (Phase 2) и P2P (после MVP).

## Открытые вопросы

1. Нужен ли C Tor fallback для старых Android? Решение после профилирования.
2. Как часто обновлять Arti? Предварительно — каждый security release,
   через ADR/CI, не автоматически в прод.
