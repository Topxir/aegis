# ADR-0006 — Argon2id для OPAQUE и экспорта

- Статус: **ПРИНЯТО**
- Дата: 2026-10-30
- Компоненты: `aegis-account`, `aegis-core::identity`, `aegis-core::storage`
- Связанные решения: `D-0024`, `D-0025`, `D-0026`

## Контекст

Argon2id нужен как KSF для OPAQUE и как KDF для явного зашифрованного
экспорта. Пароль не должен храниться на сервере; seed не должен выводиться
из пароля. Прототип не использовал Argon2id (`B-0094`).

## Решение

Использовать `argon2` (RustCrypto):

- crate: `argon2`;
- версия: `0.6.0`;
- лицензия: MIT OR Apache-2.0;
- MSRV: 1.85;
- репозиторий: `https://github.com/RustCrypto/password-hashes`;
- алгоритм: **Argon2id**, version `0x13`;
- выход: 32 байта;
- соль: 16 байт из OS CSPRNG;
- базовые параметры: `m = 64 MiB`, `t = 3`, `p = 1`;
- параметры хранятся рядом с записью/экспортом и версионируются;
- параметры можно повышать; понижать — только через ADR и с миграцией.

### Где используется

1. OPAQUE KSF (opt-in account service).
2. Явный зашифрованный экспорт истории (по паролю пользователя).
3. Не используется для генерации seed: seed — 32 случайных байта.

### Почему 64 MiB

64 MiB, t=3, p=1 — консервативный baseline для desktop и современных
Android. На слабом Android параметры замеряются в Phase 1/2; если 64 MiB
приводят к ANR/OOM, допускается 32 MiB с повышением t, но не ниже
рекомендаций OWASP и только через обновление ADR. Параметры всегда
записываются в запись, чтобы старые данные можно было открыть.

## Почему argon2

- RFC 9106, memory-hard, side-channel устойчивее, чем PBKDF2/scrypt в
  некоторых сценариях.
- RustCrypto, активно поддерживается.
- MIT/Apache-2.0 совместимы с AGPL-3.0-or-later.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| PBKDF2 | Слабее против GPU/ASIC при разумных параметрах |
| scrypt | Хорош, но Argon2id — современный стандарт и уже выбран в D-0012 |
| Argon2i/d | Argon2id — гибрид, рекомендуется RFC 9106 |
| Свой KDF | Запрещено |

## Лицензия и AGPL

MIT OR Apache-2.0. Совместимо с AGPL-3.0-or-later.

## Аудит и происхождение

- RustCrypto implementation; публичный аудит конкретной версии `0.6.0`
  не подтверждён.
- Алгоритм стандартизирован RFC 9106; это не заменяет аудит кода.
- Внешний аудит параметров и использования — до 1.0.
- При пине проверить OSV/RustSec.

## Известные CVE

На 2026-10-30 OSV не возвращает известных уязвимостей для `argon2 0.6.0`.
Проверять при каждом обновлении.

## Риски и ограничения

| Риск | Смягчение |
|---|---|
| Слабый пароль | Сильная политика, Argon2id, rate limit, предупреждение |
| Слишком высокие параметры → DoS | Benchmark; лимиты; параметры в записи |
| Слишком низкие параметры | Минимум OWASP; ADR для понижения |
| Утечка пароля в лог | Запрет логирования; тесты; review |
| Нет аудита версии | Внешний аудит до 1.0 |

## План проверки

1. RFC 9106 test vectors.
2. Замер времени/памяти на слабом Android и desktop.
3. Проверка, что параметры сохраняются и старые записи открываются.
4. Проверка, что пароль/производные ключи не попадают в логи.
5. Фаззинг паролей/граничных значений.

## Открытые вопросы

1. Финальные параметры после benchmark: 64 MiB/t=3 или 32 MiB/t=4?
2. Нужен ли отдельный pepper? Предварительно нет: pepper нужно хранить
   отдельно, это усложняет восстановление.
