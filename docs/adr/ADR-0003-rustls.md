# ADR-0003 — rustls для TLS 1.3

- Статус: **ПРИНЯТО**
- Дата: 2026-10-30
- Компоненты: `aegis-core::transport`, `aegis-relay`, `aegis-account`,
  `aegis-blob`
- Связанные решения: `D-0024`, `D-0026`

## Контекст

Прототип использует plain TCP/HTTP; `DirectTls` — только название
(`B-0095`). Нужен TLS 1.3 для relay, account service, blob store и key
server, с pinning и без plain HTTP. TLS-библиотека не должна быть
самописной.

## Решение

Использовать `rustls`:

- crate: `rustls`;
- версия: `0.23.46` (stable; ветка `0.24` пока dev и не используется);
- лицензия: Apache-2.0 OR ISC OR MIT;
- MSRV: 1.71;
- только TLS 1.3; TLS 1.2 отключён;
- certificate/SPKI pinning для relay/account/blob/key server;
- системные корневые сертификаты не используются для внутренних сервисов;
- plain HTTP запрещён; любой HTTP-запрос уходит только через TLS 1.3 +
  OHTTP/Tor.

### Криптопровайдер

`rustls` 0.23 поддерживает `ring` и `aws-lc-rs`. Кандидат — `ring`
(проще сборка на Android/Windows, меньше C/asm). Окончательный выбор —
Phase 1 spike: проверить aarch64 Android, Windows GNU, размер бинарника и
доступность обновлений. Провайдер фиксируется feature-флагами и
`Cargo.lock`; смена — через обновление ADR.

## Почему rustls

- Memory-safe TLS на Rust.
- TLS 1.3 по умолчанию, современные cipher suites.
- Гибкая проверка сертификатов/ключей для pinning.
- Apache-2.0/ISC/MIT совместимы с AGPL-3.0-or-later.
- Широко используется в Rust-экосистеме.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| `native-tls` / OpenSSL | Платформенные различия, C-код, сложнее pinning |
| `boring` / `aws-lc-rs` напрямую | Больше C/asm и сборочной сложности; допустимы как провайдер rustls |
| Свой TLS | Запрещено |
| QUIC | Не нужен в MVP; можно добавить после стабилизации TLS/Tor |

## Лицензия и AGPL

Apache-2.0 OR ISC OR MIT. Все варианты совместимы с AGPL-3.0-or-later.
Сохранить `LICENSE-*` и уведомления в `THIRD_PARTY_LICENSES`.

## Аудит и происхождение

- Публичного полного аудита именно `0.23.46` не подтверждено.
- rustls широко используется; код на Rust, но криптопровайдер (`ring` или
  `aws-lc-rs`) содержит C/asm и имеет собственный периметр аудита.
- Внешний аудит TLS-конфигурации и pinning — до 1.0.
- При пине проверить OSV/RustSec и RustSec advisory для rustls и
  провайдера.

## Известные CVE

На 2026-10-30 OSV не возвращает известных уязвимостей для `rustls 0.23.46`.
Проверять при каждом обновлении и отдельно для выбранного провайдера.

## Риски и ограничения

| Риск | Смягчение |
|---|---|
| Ошибка в pinning | Тесты с подменённым сертификатом; fail closed; review |
| Системные корни случайно включены | Явный custom verifier; тест «неизвестный CA → отказ» |
| Провайдер с C/asm | Выбрать один, документировать, аудит зависимостей |
| TLS 1.2 downgrade | Явно отключить; тест на попытку downgrade |
| Нет аудита версии | Внешний аудит до 1.0 |

## План проверки

1. Тест: TLS 1.3 handshake с pinned ключом; неверный ключ → отказ.
2. Тест: TLS 1.2 client hello → отказ.
3. Тест: self-signed/чужой CA → отказ.
4. Тест: MITM-прокси → отказ.
5. Сборка Android aarch64 и Windows GNU с выбранным провайдером.
6. `cargo deny`/`cargo audit`/SBOM.

## Открытые вопросы

1. `ring` или `aws-lc-rs`? Решение после spike.
2. Pin по SPKI или по полному сертификату? Предварительно SPKI + срок
   действия; ключ ротации — через directory descriptor.
