# ADR-0002 — OpenMLS для групп MLS

- Статус: **ПРИНЯТО**
- Дата: 2026-10-30
- Компонент: `aegis-core::groups`
- Связанные решения: `D-0024`, `D-0025`, `D-0026`

## Контекст

Группы в Aegis v2 появляются в бете после стабилизации 1:1. Максимум —
20 участников. Нужен RFC 9420 MLS с TreeKEM, epoch rotation, forward secrecy
и post-compromise security. Самописный `epoch_secret` из прототипа
запрещён (`B-0096`).

## Решение

Использовать `openmls`:

- crate: `openmls`;
- версия: `0.9.2`;
- лицензия: MIT;
- MSRV: 1.91.0;
- репозиторий: `https://github.com/openmls/openmls/`;
- только для групп Phase 4; 1:1 остаётся на libsignal;
- группа ≤ 20 участников;
- сообщение MLS шифруется, затем оборачивается в pairwise-конверты для
  каждого участника, чтобы relay не видел `group_id`;
- add/remove/commit/epoch — через публичное API OpenMLS, без своей
  реализации TreeKEM.

## Почему OpenMLS

- Реализация RFC 9420 на Rust.
- Активно развивается, есть тестовый набор и примеры.
- MIT совместим с AGPL-3.0-or-later.
- Позволяет не писать свою групповую криптографию.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Свой `epoch_secret` | Не MLS; нет PCS/FS; запрещено |
| `mls-rs` (AWS) | Возможная альтернатива; меньше проверен в Rust-экосистеме Aegis; рассмотреть при проблемах с OpenMLS |
| `openmls` + свои расширения | Допустимо только через ADR; не менять базовый протокол |
| Группы через попарные Double Ratchet | Не масштабируется; нет MLS-свойств; для 20 участников — 190 сессий |

## Лицензия и AGPL

MIT. Совместим с AGPL-3.0-or-later. Уведомление об авторских правах
сохраняется в `THIRD_PARTY_LICENSES`.

## Аудит и происхождение

- Публичный аудит конкретной версии `0.9.2` не подтверждён.
- MLS RFC 9420 имеет формальный анализ и несколько независимых
  реализаций; это не заменяет аудит кода.
- OpenMLS должен входить в периметр внешнего аудита до 1.0.
- При пине проверить OSV/RustSec и GitHub Security Advisories.

## Известные CVE

На 2026-10-30 OSV не возвращает известных уязвимостей для `openmls 0.9.2`.
Проверять при каждом обновлении.

## Риски и ограничения

| Риск | Смягчение |
|---|---|
| API churn и MSRV 1.91 | Пин на версию; обновление через ADR; CI с закреплённым toolchain |
| Сложность group state | Тесты add/remove/epoch, fuzzing, multi-client сценарии |
| Группа ≤ 20 | Явный лимит в протоколе и UI; больше — после отдельного решения |
| Pairwise wrap раскрывает число участников | Паддинг и батчинг; residual risk в threat model |
| Нет аудита версии | Внешний аудит до 1.0 |

## План проверки

1. RFC 9420 test vectors / тесты OpenMLS.
2. Сценарии: create, add, remove, commit, epoch rotation, welcome.
3. Проверить, что удалённый участник не читает новые сообщения.
4. Проверить forward secrecy и post-compromise security на тестовых
   сценариях.
5. Фаззинг парсеров MLS-сообщений.
6. Multi-client тест с 20 участниками.

## Открытые вопросы

1. Нужны ли MLS extensions (например, для метаданных группы) или только
   базовый RFC 9420?
2. Хранить group state в SQLCipher или отдельном encrypted blob?
   Предварительно — SQLCipher, с тем же ключом БД.
