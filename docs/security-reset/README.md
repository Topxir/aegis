# Security Reset v2 — план и спецификация (rev.2)

**Статус: УТВЕРЖДЕНО владельцем 2026-10-30. Код не менялся.**

Ревизия 2 утверждена владельцем 2026-10-30. Документы v0.1 были возвращены
на доработку; ниже — что изменено и что входит в Phase 0.

Это не описание уже готовой защиты и не рекламный документ. Это честный план
перехода от текущего прототипа Aegis к ядру, которое можно будет хотя бы
проверять внешними аудиторами.

## Почему понадобился reset

Проверка текущего репозитория показала критическое расхождение между
документацией и кодом:

- в `Cargo.lock` нет ни одной внешней зависимости — вся криптография,
  «OPAQUE», ratchet, TLS и серверная логика написаны с нуля;
- `aegis-identity` использует HMAC-схему под названием «OPAQUE», но это не
  RFC 9807 и не Argon2id;
- `aegis-transport` работает поверх обычного TCP/HTTP; режим `DirectTls` —
  только название, TLS 1.3 и пиннинга сертификата нет;
- `aegis-serverd` слушает `http://` и вручную разбирает HTTP;
- группы в `aegis-protocol` — общий `epoch_secret`, а не MLS;
- реального X25519/ML-KEM/Ed25519 в старом ядре нет, только комбинатор
  секретов;
- встроенного Tor нет: `TorArtiEmbedded` — только вариант enum;
- по умолчанию используются прямые статические IP, что раскрывает IP
  пользователя серверу и провайдеру;
- iOS-приложения нет;
- 98 тестов проходят, но они проверяют самописную реализацию самой собой.

Подробный разбор — в [`THREAT_MODEL_V2.md`](THREAT_MODEL_V2.md) и
[`../reports/2026-10-30_T-0017.md`](../reports/2026-10-30_T-0017.md).

## Решения владельца (2026-10-30)

1. Пока только план и спецификация, без изменений кода.
2. Идентичность: инвайты + ключи, без глобального ника. Пароль OPAQUE
   сервер не хранит (только verifier); OPAQUE — opt-in.
3. Сеть: встроенный Tor по умолчанию + OHTTP для API.
4. Репозиторий приватный до внутреннего red team; затем public alpha с
   меткой «unaudited»; внешний аудит — до 1.0.
5. Сначала Android + Desktop; iOS позже.
6. MVP: 1:1 текст + файлы; группы — в бете.
7. Ресурсы: соло, без бюджета; внешний аудит — позже, когда будет
   финансирование.
8. Identity key: libsignal XEd25519 (Curve25519 + XEdDSA), не отдельная
   пара Ed25519 + X25519.
9. OPAQUE-аккаунт: opt-in; seed-only остаётся режимом по умолчанию.
10. Public alpha: после внутреннего red team; внешний аудит — до 1.0.
11. P2P onion: после MVP, не в MVP.
12. Максимум группы в бете: 20.
13. Бэкап: только явный зашифрованный экспорт; автоматического cloud
    backup нет.

## Что изменено в ревизии 2

- **Identity:** вместо отдельных Ed25519 + X25519 — libsignal identity key
  (Curve25519 + XEdDSA). `AIK` — корень аккаунта, `DIK` — ключ устройства.
  Отдельный Ed25519 остаётся только для инфраструктурных подписей.
- **Invite v2:** добавлены `account_pub`, `device_pub`,
  `device_credential`; убран `max_uses`; инвайт — контактная карточка, а не
  одноразовый ресурс.
- **Inbox:** `inbox_id` выводится из `read_token`; регистрация inbox не
  нужна; `POST /v1/inbox` отсутствует; read token не в инвайте.
- **OPAQUE:** opt-in account service; OPAQUE RFC 9807 + Argon2id; сервер
  хранит verifier и зашифрованный seed-backup, не пароль и не сообщения.
- **Public alpha:** после внутреннего red team, с честной меткой
  «unaudited»; внешний аудит — до 1.0.
- **P2P:** после MVP.
- **Группы:** ≤ 20 в бете.
- **Бэкап:** только явный зашифрованный экспорт; OPAQUE seed-backup — не
  история чата.
- **Message franking:** отложен; свою схему не пишем.

## Честный статус

- Это **не** «самый защищённый мессенджер в мире». Это план, как перестать
  быть самописным прототипом и приблизиться к лучшим практикам.
- Без внешнего аудита, bug bounty и воспроизводимых сборок слово
  «защищённый» использовать нельзя. Public alpha будет помечен
  «unaudited».
- Абсолютной защиты от государства, глобального пассивного наблюдателя,
  malware на устройстве и принуждения пользователя не существует.
- «Даже создатель не узнает» — это дизайн-цель, а не математическая
  гарантия. Слепой relay, отсутствие логов и reproducible builds сильно
  снижают риск, но злонамеренный разработчик всё равно может выпустить
  бэкдорную сборку. Защита — независимые сборщики и аудит.
- «Невозможно удалить» применимо к коду и сети (форки, зеркала, федерация,
  P2P позже), но не к сообщению на устройстве получателя. Исчезающие
  сообщения — best effort.
- OPAQUE-аккаунт — это дополнительный серверный сервис. Он не видит
  сообщения, но видит `account_id` и login timing; при одном операторе с
  relay возможна корреляция.
- Инвайт не является криптографически одноразовым. Если нужна one-time
  ссылка, это отдельный дизайн с relay-side state.
